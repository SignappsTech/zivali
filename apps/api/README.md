# apps/api

Express 5 + Prisma 7 REST API and the pg-boss worker, in the client's klikni layout ([ADR-020](../../docs/tech/adr/020-api-architecture.md)). Supabase provides only Postgres, Auth and Realtime; every business rule and permission check lives here. Conventions for endpoints, errors, migrations, jobs and seeds: [C1](../../docs/tech/contracts/C1-platform-conventions.md) and [backend.md](../../docs/tech/backend.md).

## Layout (no `src/`)

```
app.ts                      Express app, middleware in ADR-020 order (request id → pino-http → helmet → cors →
                            compression → json 1 MB → global rate limit → /ping, /v1 → 404 → error middleware)
server.ts                   HTTP entry; SIGTERM/SIGINT: stop accepting, finish requests, disconnect Prisma
worker.ts                   worker entry, same image (`node dist/worker.js`): pg-boss, schedules, the jobs/ handlers
jobs/<queue>.job.ts         one handler per queue, `handle(data, ctx)`; jobs/index.ts is the queue registry (runJob)
routes/index.ts             the /v1 router: one mount line per area
routes/<area>.routes.ts     one Router per area, routes declared with apiRoutes() (validation + OpenAPI, below)
openapi.json                generated, committed OpenAPI 3.1 document (`gen:openapi`); RTK Query codegen input
controllers/<area>.controller.ts   thin: req → ctx → domain → mapper → res (no try/catch)
domains/<area>/             all business logic, HTTP-agnostic
  <thing>.domain.ts           (input, ctx) → result; rules, permissions, ownership, transactions; throws AppError
  <area>.dao.ts               Prisma only; every function takes tx?: Prisma.TransactionClient
  <area>.mapper.ts            domain/Prisma result → response DTO, parsed with the DTO schema
  index.ts                    the area's public functions (the DAO stays private)
middleware/<name>.middleware.ts    requestId, validate, error, auth, permission, rateLimit, idempotency (below)
lib/                        config.ts (zod env, read once), logger.ts (pino), errors.ts (AppError + C1 codes),
                            ctx.ts (userCtx, systemCtx), jobs.ts (pg-boss: QUEUES, SCHEDULES, jobs.send, drain), config-store.ts (app_config, 60 s), crypto.ts, openapi.ts (apiRoutes over the @zivali/validation registry)
scripts/gen-openapi.ts      writes openapi.json; `--check` fails when it is stale (part of `lint`)
scripts/admin-create.ts     `pnpm admin:create <email>`: promotes a confirmed account to ADMIN (local stack only, else
                            `--i-know-this-is-production` + typing the email again); never an HTTP endpoint (ADR-018)
scripts/jobs-drain.ts       `pnpm jobs:drain`: runs queued jobs through the registry until the queues are empty
prisma/                     prisma.ts (client singleton), schemas/*.prisma + schemas/migrations/,
                            seed.ts (runs seeders/NN-<name>.seeder.ts in order)
generated/                  Prisma client output (gitignored, never edited; `prisma generate` rebuilds it)
test/                       routes/, middleware/, lib/, jobs/, security/, helpers/ (signTestToken), setup.ts, global-setup.ts
```

`domains/health` is the sample area: `GET /v1/health/ready` → `HealthController.ready` → `HealthDomain.getReadiness` → `HealthDao.pingDatabase` → `HealthMapper.toReadyDto`.

## Declaring a route (validation and OpenAPI in one place)

Every route goes through `apiRoutes(router, '/v1/<area>')` in its `routes/<area>.routes.ts`. One declaration adds `validate()` for the request schemas in Express (params, query, body; then your guards and the controller) and registers the same schemas in the OpenAPI registry, so the docs cannot drift from the validation:

```ts
const router = Router();
const route = apiRoutes(router, '/v1/reports');

route(
	{
		method: 'get',
		path: '/:id',
		operationId: 'getReport',
		summary: 'One public report',
		description: 'Fuzzed location only; the exact point is never returned (C4).',
		request: { params: ReportIdParams },
		responses: { 200: { description: 'The report', schema: ReportDetailSchema } },
		errors: ['NOT_FOUND', 'GONE'],
	},
	optionalAuth,
	ReportsController.getById
);
```

- `operationId`: stable, unique (checked at startup), camelCase verb + noun (`getReport`, `createLostReport`, `listNearbyReports`). The RTK Query codegen (`@rtk-query/codegen-openapi`) turns it into the endpoint and hook name (`useGetReportQuery`); renaming it renames the client hook.
- Tag: the area (`reports`), from the base path; the codegen groups endpoints by it.
- Errors: list the C1 codes the route can return besides the automatic `VALIDATION` (when it has request schemas), `RATE_LIMITED` and `INTERNAL`; they are documented per HTTP status with the `ApiErrorBody` schema from `@zivali/validation`.
- Named types: shared request and response schemas live in `@zivali/validation` with `.openapi('ReportDetail')` and are registered as components automatically; an API-only schema gets `.meta({ id: 'HealthReady' })`. Unnamed schemas end up as inline shapes in the generated client.
- After changing a route or schema, run `pnpm --filter api gen:openapi` and commit `openapi.json`; `pnpm verify` fails while it is stale.

## Where does logic go

| Concern                                                                                                    | Place                                                                       |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Request shape (body, query, params)                                                                        | zod schema (`@zivali/validation` once it exists), `validate()` in the route |
| Authentication, role, aal2, verified email, rate limit                                                     | route guards (middleware)                                                   |
| Ownership ("manager of this report", "participant of this conversation"), limits, state machines, any rule | domain function                                                             |
| Database reads and writes                                                                                  | DAO in the same area (`tx ?? prisma`)                                       |
| HTTP status, headers, cookies, redirects                                                                   | controller only                                                             |
| Response shape                                                                                             | mapper in the area                                                          |
| Background work                                                                                            | job handler in `jobs/` calling domain functions                             |
| Scripts, seeders, admin tools, tests                                                                       | call domain functions with `systemCtx()` or `userCtx(actor)`                |

A domain function never imports Express, never reads `req`/`res`, and never catches an error just to rethrow it. Catch locally only where you handle it (retry, fallback, mapping a unique violation to a domain error); `getReadiness` is the example.

Errors: throw `new AppError(code, message?, details?)`. The error middleware renders `{ error: { code, message, details?, issues? } }` with the C1 status; `ZodError` → `VALIDATION` with dotted-path `issues`, Prisma `P2002` → `CONFLICT`, `P2025` → `NOT_FOUND`, anything else → `INTERNAL` (logged with `req_id`, nothing leaked).

Logs (pino, `lib/logger.ts`): one line per request with `req_id`, `route` (method and pattern, e.g. `GET /v1/reports/:id`), `status` and `duration_ms`. URLs, query strings, headers and bodies are never logged, and the keys `lat`, `lng`, `point`, `near`, `location`, `body` and `query` are removed from any log line (C1, C6). Log through `ctx.logger` or `req.log`; `console.*` is a lint error.

## Database (ADR-021)

- `DATABASE_URL` and `DIRECT_URL` must end with `?schema=app`; `lib/config.ts` and `prisma.config.ts` refuse anything else. Prisma then keeps its migrations table in `app`, and `migrate reset` drops only `app`, never Supabase's `public`.
- Models: one file per domain in `prisma/schemas/`, `@@schema("app")` on every model, RLS enabled in the migration.
- The first migration (`TASK-3.7`) creates schemas `app` and `pgboss`, enables `postgis`, `vector` and `pgcrypto` in `extensions`, and revokes everything on `app` and `pgboss` from `public`, `anon` and `authenticated`.
- Platform models (`TASK-6.2`): `profiles` (`users.prisma`, C3), `app_config`, `audit_log`, `rate_limits`, `idempotency_keys` (`platform.prisma`, C1). Every table in `app` and `pgboss` has RLS enabled and no policies; `test/security` proves it, plus no grants and no PostgREST exposure.
- PostGIS types are schema-qualified in `Unsupported(...)` (`extensions.geography(Point,4326)`): with `?schema=app` the search path does not include `extensions`.
- Every new model gets an entry in `prisma/data-inventory.json` (with each R2 bucket); `test/security/data-inventory.test.ts` fails otherwise.
- Seed: fixture users, password and the local TOTP secret for mod and admin are in [prisma/seeders/README.md](prisma/seeders/README.md).
- Prisma 7 no longer generates on `migrate dev`: run `pnpm --filter api exec prisma generate` after schema changes (`pnpm install` also does).
- Geo reference (`TASK-6.4`, `geo.prisma`): `regions` and `municipalities` (GURS, GiST on `geom`), loaded by seeder `01-geo` in every environment. `GeoDomain.lookup({ lat, lng }, ctx)` (`lib/geo.ts`, one raw PostGIS query) returns the municipality and region ids and slugs, or `in_slovenia: false`.
- Commerce and moderation (`TASK-6.8`): `abuse_reports`, `moderation_flags` (`abuse.prisma`, C11), `payments`, `payment_events` (`payments.prisma`, C13), `ads`, `ad_stats_daily`, `partner_stats_snapshot`, `leads` (`ads.prisma`, C14), `organisations`, `organisation_members` (`organisations.prisma`). Value lists, https ad links, ad alt text 5–140 and the EUR 2.00 minimum are database checks; `app_config` `payments.prices` (cents) and `payments.live_allowed` (false) come with the migration. Seeder `30-commerce` loads the house ads everywhere and local fixtures (sponsor ads, a verified shelter).
- Staging and prod reference data: every deploy runs the seed after `prisma migrate deploy` (`deploy/remote.sh`; the bundle `dist/seed/` from tsup, with the seeders' data copied in by the Dockerfile). The all-environment seeders (`01-geo`, `02-geo-places`, `05-directory`, `30-commerce` house ads) are idempotent and keep admin edits; the fixture seeders skip themselves via `APP_ENV`.
- Reports, pets, photos (`TASK-6.6`, `reports.prisma`, `photos.prisma`): the points are `geography` columns, written and read only in `domains/reports/reports.dao.ts` (`$queryRaw`). Every report location write goes through `ReportsDomain.insertReport` / `updateReportLocation`: `coarsenPoint()` once (20–30 m, random; the received point is never stored), then the public circle from `lib/fuzz.ts` (HMAC with `FUZZ_SECRET` over the report id and the stored point, offset from the type's minimum radius only, minima and grid from `app_config` `fuzz.*`) and the geo lookup of the circle's centre (municipality, region and `in_slovenia` are public). A radius-only change keeps `public_point` and updates `public_radius_m`. `GET /v1/reports/:code` maps through `ReportsMapper` (PublicReport, or ReportOwnerView for managers).
- Photos (`TASK-14.1`, C5, ADR-014, `domains/photos`): `POST /v1/photos` returns a 5-minute presigned PUT (image/jpeg, length pinned) to `uploads/<owner>/<id>.jpg` in the private bucket; `/complete` queues `photo.process` (size, JPEG magic bytes, SHA-256, then sharp: EXIF orientation applied, all metadata dropped, `variants/<id>/{display.webp,display.jpg,thumb.webp}`; the upload is deleted). `photo.publish { report_id }` copies accepted variants of a visible report to the media bucket (`r/<report>/<photo>/…`, URLs under `MEDIA_BASE_URL`, locally the MinIO bucket URL) and deletes them when the report is held, hidden, removed, expired or closed > 30 days: send it from every write that changes a report's visibility or photos. Detaching a published photo (PATCH `photo_ids`) unpublishes it and queues `retention.purge { objects }` for its public copies; `MEDIA_BASE_URL` is required outside `APP_ENV=local`. `retention.purge` deletes the rows first (purge predicate re-applied, so a touched or attached photo stays) and queues their objects in the same transaction; it removes photos unattached for 24 h (`updated_at` is the clock; deleted pets detach theirs) and photos of reports ended 12 months ago. `PHOTO_HOOKS` (`ai.extract`) lists the queues each accepted photo is sent to (M3). Tests run on the in-memory storage adapter (`vitest.config.ts`).
- AI attribute extraction (`TASK-40.3`, C19, ADR-012, `domains/ai`): `ai.extract { photo_id }` → `AiDomain.extractPhoto`: nothing for a photo not created after `app_config` `ai.photos_since` (the AI switch-on, TASK-40.11; unset or invalid = no photo, also in `photo.embed` and the backfill; set to the time the switch-on migration ran, locally too; the worker logs it at start, deploy/README.md §11), else the `ai_results` row of the same sha256 (outcome `cached`), else the caps in order (`ai.enabled` or `AI_PROVIDER=off` → `skipped_disabled`, the month's Anthropic spend ≥ `ai.monthly_budget_usd` → `skipped_budget`, the owner's provider calls in 24 h ≥ `ai.daily_photos_anonymous`/`ai.daily_photos_user` → `skipped_limit`), else one call with `display.jpg` at 1024 px. The adapter clamps confidences, drops other-species breeds and cuts breeds, colours and marks to 3/3/5 on the raw JSON, then `aiExtractionSchema.safeParse` (`refused`, `invalid`; a rejected request, 400/401/403/404/422, is `failed` at once; 429, 5xx and connection errors retry, the last attempt records `failed`). One `ai_calls` row per photo (cost from `domains/ai/pricing.ts`), then `photo.embed` unless flagged or not a dog or cat; logs `ai.extract.done`. `AI_PROVIDER` unset is the mock locally and `off` in staging and production; the mock never runs outside `APP_ENV=local` (`mock`, or `anthropic` without a key, is `off` there). The mock (`adapters/ai/mock.ts`) answers from `test/fixtures/ai/` by sha256 (`index.json`: refusal, invalid, person). `retention.purge` drops `ai_calls` after 62 days and `ai_results` no photo has the hash of.
- Photo attributes (`TASK-40.4`, C19 §REST, `routes/photo-attributes.routes.ts`): `GET /v1/photos/:id/attributes` (owner only, signed-in or anonymous; anyone else's, unknown or rejected photos are `NOT_FOUND`; `rate.photos.attributes` 600/h; `Cache-Control: private, no-store`) → `AiDomain.getPhotoAttributes`: `pending` until the photo is accepted and has an Anthropic `ai_calls` row, `ready` for `ok`/`cached` with an `ai_results` row that still passes `aiExtractionSchema`, else `unavailable`. `AiMapper.toPhotoAttributes` nulls values below `ai.min_confidence` (unset or not a number: all null), keeps at most 2 breed codes at or above it with the best one's confidence, and answers `no_animal`/`other_animal` with no suggestions; moderation, marks, the model and the ledger never go out.
- Report writes (`TASK-29.2`, C4): `POST /v1/reports` (auth, `rate.reports.create` 30/h, `Idempotency-Key` required) → `ReportsDomain.createReport`: lost reports need a real account, `submission-guard.ts` runs first (stub: always `visible`; TASK-17.1 adds the anonymous rules and holds), then the field rules (`event_at` ≤ now + 10 min, older than 30 days → `warnings: ['OLD_EVENT']`, name, pet, radius and reward on lost reports only, `DUPLICATE_OPEN_REPORT` per pet, own unattached photos only) and one transaction with the report, its manager, its photos and the ids-only jobs `photo.publish`, `match.report` and, for visible lost reports, `alerts.fanout`. `PATCH /v1/reports/:code` (managers; removed, closed and reunited → `GONE`) re-queues `match.report` when the point or a matching input changes, `alerts.fanout` when the point of a visible lost report moves, `photo.publish` when `photo_ids` is sent. `ReportsDomain.releaseReport({ id }, ctx)` (moderator or system ctx) turns held into visible and queues the same three jobs as a create. `GET /v1/me/reports` lists the caller's managed reports (ReportOwnerView, keyset by id).
- Ad serving (`TASK-35.1`, C14, `domains/ads`): `GET /v1/ads/slot/:slot` (optionalAuth, `private, max-age=60`; slots `feed`, `detail`, `reunited`, `sidebar`, anything else `VALIDATION`) picks among active, in-date ads for the slot and locale whose `region_ids`, `municipality_ids` and `species` are each NULL/empty or contain the context (region derived from `municipality_id` when absent): an exclusive match owns the slot, else weighted random by `weight`, else a house ad for the locale; `null` only when not even a house ad fits (nobody is ad-free until Premium, M4). `POST /v1/ads/:id/impressions` (`rate.ads.impressions` 300/min per IP hash) adds 1 to `ad_stats_daily` (day in Europe/Ljubljana, unknown region → 0) in one `INSERT … ON CONFLICT`. `GET /v1/ads/:id/click?s=<slot>&r=<region_id>` (`rate.ads.clicks` 300/min per IP hash, no cookies, `Cache-Control: no-store`) adds 1 click the same way for an active ad that runs in the slot and answers 302 to the ad's stored https `link_url`, the only possible target (no URL from the request is ever followed); anything else is 404. Content rule: `BLOCKED_CATEGORIES` (sale, giveaway, rehoming) plus `app_config` `ads.blocked_terms` (string[], SL and EN, from the migration) are whole-word matches on title, body, CTA, alt text and link, ignoring case and diacritics; checked on every serve and by `AdsDomain.assertAdWritable(input, ctx)`, which every ad save calls (admin + aal2, content, no exclusive overlap per slot and region).
- Partner stats and leads (`TASK-38.2`, C14, `domains/partners`): the hourly `partners.stats` job stores masked counts (1–4 → `'<5'`, DB only; `app_config` `partners.pilot` true, `partners.ga_enrichment` false) in `partner_stats_snapshot` (kept 90 days); `GET /v1/partners/stats` serves the newest (`public, max-age=3600`). `POST /v1/leads` (captcha adapter, `rate.leads` 3/h per IP) stores the lead with `consent_at` and emails `LEADS_NOTIFY_EMAIL` (unset or failed: stored anyway, logged by id); `GET /v1/admin/leads` (admin, aal2, audited).
- `FUZZ_SECRET` rotation: only on a suspected leak (whoever holds the key can search a circle for the stored point that yields its centre). Existing circles stay as they are, because `public_point` is stored; the new key applies to new reports and moved locations. Never log the secret or put it in job payloads.

## Auth and platform middleware (C1, C3)

```ts
route(
	spec,
	authMiddleware,
	rateLimit('reports.create', { limit: 10, window: 3600, key: 'user' }),
	requireVerifiedOrAnonymous,
	idempotency({ required: true }), // last, right before the controller
	ReportsController.create
);
route(spec, authMiddleware, requireRole('moderator'), requireAal2, AdminController.list);
```

- `authMiddleware` verifies the Supabase access token with `jose` against `${SUPABASE_URL}/auth/v1/.well-known/jwks.json` (audience `authenticated`, issuer, exp); the HS256 `SUPABASE_JWT_SECRET` is accepted only when `APP_ENV=local`. It sets `req.user = { user_id, role, is_anonymous, aal, email_verified, locale }` with role and locale from `app.profiles` and `email_verified` from `auth.users.email_confirmed_at` (never from `user_metadata`, which users can write), cached 60 s (`invalidateProfile(id)` after a role change), and creates a missing profile (`ensureProfile`). `optionalAuth` never answers 401.
- Guards (`permission.middleware.ts`): anonymous finders count as signed out (`UNAUTHENTICATED`) except in `requireVerifiedOrAnonymous`; `requireVerified` → `UNVERIFIED_EMAIL`, `requireRole('moderator' | 'admin')` → `FORBIDDEN`, `requireAal2` → `AAL2_REQUIRED`, `rejectAnonymous`.
- `rateLimit(name, { limit, window (s), key: 'user' | 'ip' | 'device' })`: fixed window in `app.rate_limits`, IPs and `x-device-id` stored as HMAC (`RATE_SALT`); `key: 'user'` counts anonymous finders per device (else IP), signed-out callers per IP; `app_config` `rate.<name>` = `{ limit, window }` overrides the code values (positive integers, window ≤ 172 800 s, else ignored); 429 with `Retry-After`.
- `idempotency({ required })` last, right before the controller (after auth and guards): same user + key + route + body (canonical JSON, SHA-256) within 24 h replays the stored response (`Idempotent-Replayed: true`); another user, route or body, or a running first request → 409 `CONFLICT`; bodies stored encrypted (`IDEMPOTENCY_KEY`); 5xx, 429, 401 and 403 are not stored.
- Staff and destructive services write `AuditDao.write(tx, { actor_id, action, target_type, target_id, diff, note })` (`domains/platform`). `PlatformDao.purgeExpired(now)` is for the retention job.
- Jobs (ADR-022): `ctx.jobs.send(queue, data, { tx?, singletonKey?, startAfter? })`, with `tx` the job exists only if the transaction commits; every queue retries 5 times with backoff, then `failed`. Schedules (Europe/Ljubljana) are created by the worker. Tests call `drain(runJob)` (retries and deferred jobs run at once). `NotificationsDomain.enqueueNotification({ user_id, type, payload: { template, report_id?, … }, dedupe_key? }, ctx)` sends `notify.send` (ids and a template key only, it is stored in `pgboss.job`); the handler loads the copy variables from those ids through the type's source in `domains/notifications/sources.ts` (the feature that owns the data adds it), then stores the inbox row, broadcasts `notification.created` on `user:<id>`, and sends push and email in `profiles.locale` (C10). `sendManageLink` emails the finder's private link directly (the token never goes into a job).
- `startJobs()` (API and worker) starts pg-boss, creates the queues, then `lockDownPgboss()` (`lib/pgboss-lockdown.ts`) enables RLS on the tables pg-boss created (CH-106); if it fails, the API and the worker log `fatal` and exit 1.

## Anonymous reports and the manage link (C7)

- `domains/reports/submission-guard.ts` runs first in `createReport` for anonymous callers: per IP and per `x-device-id` hash, `app_config` `rate.anon_report_per_hour` (5) and `rate.anon_report_per_day` (20) → `RATE_LIMITED` with `Retry-After` (`consumeRateLimit`, same `app.rate_limits` table as the middleware). It holds the report (`held`, an `anon_hold` moderation flag with the reasons) when the device already sent 10 reports in 7 days (`reports.device_hash`, cleared after 7 days by `retention.purge`) or a photo's sha256 matches a photo of a held or removed report.
- Anonymous creates return `manage_token` (32 random bytes, base64url; only its SHA-256 is in `reports.manage_token_hash`; the idempotency replay returns the same token from the encrypted store). `finder_email` (anonymous only) goes to `report_contacts` and gets the link by email right after the commit (`ManageDomain.mailManageLink`, a failed email never fails the request).
- `POST /v1/manage/claim { token }` (10/hour per IP) makes the caller a `finder` manager; `GONE` for removed reports or ones closed more than 7 days ago. `POST /v1/reports/:code/manage-link/resend` (managers, 3 per report per day) emails a new token; the old link stops working. The new token is emailed first (no transaction open) and its hash written only after a successful send, so a failed email changes nothing (500) and the old link keeps working. `consumeRateLimit` (`domains/platform`) is the fixed-window helper behind the `rateLimit` middleware and these domain limits.
- Converting the anonymous user to an account keeps the uid, so every `report_managers` row stays; the first request with the non-anonymous token flips `profiles.is_anonymous`.

## Chat and Realtime (C9, ADR-023)

- `/v1/conversations` (`routes/conversations.routes.ts`, `domains/chat`): participants only. `sendMessage` stores the message, broadcasts `message.created` on `conversation:<id>` and `conversation.updated` on each other participant's `user:<id>` with `realtime.send` in the same transaction (`lib/realtime.ts`), and queues `chat_message` (`{ template, thread_id, message_id }`, dedupe key `chat:<id>:<5-minute window>`) for participants who are not muted and have not read the conversation in the last 2 minutes (online).
- `app.can_join_topic(uid, topic)` (security definer, EXECUTE for `authenticated` only, no usage on `app`) backs the one policy on `realtime.messages`. The migration skips the policy where `realtime.messages` does not exist (shadow databases): a scratch database for the chat tests needs a Realtime server attached before migrating.
- `ChatDomain.closeForReport({ report_id }, ctx)` makes the report's conversations read-only (call it inside the close transaction); `retention.purge` deletes them with their messages `retention.chat_months` (6) after close.
- `test/routes/conversations.realtime.test.ts` (two WebSocket clients, p95 < 2 s) runs only when a Realtime server is attached to the test database (schema `_realtime`). `REALTIME_URL` overrides `${SUPABASE_URL}/realtime/v1`, e.g. `ws://realtime-dev.localhost:<port>/socket` for a Realtime container started against a scratch database.

## Payments (C13, ADR-011)

- `POST /v1/payments/checkout` (real accounts, `Idempotency-Key` required, 20/hour): integer cents; tip, report_contribution and support take the user's amount (200–50 000, below 200 → `422 MIN_AMOUNT`), boost and subscriptions answer 503 `SERVICE_UNAVAILABLE` until M4 (no effect yet, so no money is taken). report_contribution needs a report the caller manages; for tip and support a `refs.report_id` the caller does not manage is dropped. A Stripe timeout (10 s) or network failure answers 503 too. The provider session is created first, then the `pending` row (a provider failure leaves no row). Return URLs: web `APP_URL/placila/zakljucek` or `/en/payments/return` (C15), app `zivali://payments/return` (`return_scheme: true`; whether Stripe accepts the custom scheme is unconfirmed, check in the AC5 staging run), each with `?payment_id=…&return_to=…`, cancel adds `&canceled=1`. `GET /v1/payments/:id` and `GET /v1/me/payments` are owner-only.
- `POST /v1/webhooks/stripe` (`routes/webhooks.routes.ts`, mounted in `app.ts` before `express.json`): Stripe signature over the raw body (`Stripe-Signature: t=<unix>,v1=<hex HMAC-SHA256 of "<t>.<body>">`, 5-minute tolerance), `livemode: true` → `422 LIVE_MODE_FORBIDDEN`, then one transaction: the redacted `payment_events` row (duplicate event id → 200 no-op), the status move (only from `pending`; refunds from `succeeded`; a late event never moves a settled payment) and `payment.effects`. Handled: `checkout.session.completed` (paid), `…async_payment_succeeded`, `…async_payment_failed`, `…expired`, `charge.refunded` (full refunds). Events are matched by `metadata.payment_id`, the session id or the payment intent.
- `payment.effects` first issues the fiscal invoice (below), then sends `payment_receipt` once (`receipt_sent_at`): email in the recipient's locale (confirmed addresses only) and in-app, through `notify.send`; the email shows the invoice number, ZOI and EOR.
- Fiscal invoices (C13 §Fiscal invoices, TASK-92, `domains/payments/invoices.domain.ts`, `adapters/fiscal`): one `invoices` row per succeeded payment whose purpose is in `app_config` `fiscal.invoiced_purposes` (default: all), numbered `<FISCAL_PREMISE_ID>-<FISCAL_DEVICE_ID>-<sequence>` without gaps (`invoice_sequences` row lock inside the insert transaction; a rollback returns the number), VAT 22 % (`net + vat = gross`, whole cents), `issued_at` and the ZOI fixed at creation. Verification through the adapter: each attempt is claimed on `attempts` (a concurrent run retries later); a failure throws, so pg-boss retries with backoff and the retry is a FURS `SubsequentSubmit`; after 5 attempts the invoice is `FAILED` (still with its ZOI) and the receipt goes out without EOR. The worker then renders the PDF (`lib/invoice-pdf.ts`, pdfkit, fonts in `assets/fonts`) to `private/invoices/<id>.pdf`; `GET /v1/payments/:id/invoice.pdf` serves it to the owner (404 to anyone else and until it exists). `FISCAL_PROVIDER`: `mock` (default everywhere: deterministic ZOI and EOR), `furs` (FURS test environment over mutual TLS with the `FURS_*` PEM files; the production endpoint is refused), `off`. Registration steps: `deploy/README.md` §10.
- Mock provider (no Stripe keys, local and tests; `vitest.config.ts` pins it): checkout URL `APP_URL/dev/checkout?payment_id=…`. The dev page (TASK-32.2, server side) posts `mockEvent('success' | 'fail' | 'cancel', payment_id)` bodies (`adapters/payments/mock.ts`) signed like Stripe with `MOCK_WEBHOOK_SECRET` (`signWebhook`; unset locally = `mock-webhook-secret`), so the mock runs the same webhook path.
- Live gate: the adapter refuses `sk_live_`, `rk_live_` and `pk_live_` keys at boot outside `APP_ENV=production`; in production a live key boots, but `createCheckout` answers `422 LIVE_MODE_FORBIDDEN` until `PaymentsDomain.liveGateOpen`: `app_config` `payments.live_allowed` is `true` and either the fiscal adapter is live (FURS production: no provider yet) or the accountant recorded `fiscal.required = false` with `FISCAL_PROVIDER=off`. Both keys stay `false`/`null`. Livemode webhook events are accepted only with a live key, so money a live checkout took is always recorded. The Stripe account enables Managed Payments by default; sessions turn it off (`managed_payments[enabled]=false`), Najdimo stays the merchant. Every Stripe request pins `Stripe-Version: 2026-04-22.dahlia` (`adapters/payments/stripe-version.ts`, also the webhook endpoint's `api_version`); `scripts/stripe-webhook.mjs` reads the key only from the env file, requires the Najdimo sandbox account (`GET /v1/account`) and recreates an endpoint whose secret is lost only with `--recreate`.
- Staging webhook endpoint: `node scripts/stripe-webhook.mjs staging` (deploy/README.md §1).
- Premium prices (C13 §Prices and entitlements, TASK-52.1): `app_config` `payments.prices` holds `premium_monthly_cents` 399 and `premium_yearly_cents` 2999. `PaymentsDomain.premiumPrice('monthly' | 'yearly', ctx)` resolves the active provider price with lookup key `premium_monthly` / `premium_yearly` (`findPrice`, cached 10 min per adapter; a failed lookup is not cached) and answers 503 `SERVICE_UNAVAILABLE` (log `payments.price_mismatch`) when it is missing or its amount, currency or interval differs from `payments.prices`. The mock provider builds its prices from `payments.prices`. Stripe objects: `pnpm --filter api stripe:prices` (dry run) / `pnpm --filter api stripe:prices --apply` (`scripts/stripe-prices.ts`): only an `sk_test_` key from the root `.env.local` of the Najdimo sandbox account (`GET /v1/account` first); creates product `najdimo_premium` if missing and, per lookup key whose price differs, a new recurring EUR price (VAT inclusive, `transfer_lookup_key`) and archives the replaced one (never deletes); a second run changes nothing.
- **IAP risk (R-003)**: the app opens web Checkout (`openAuthSessionAsync`), no native purchase UI. App Store and Google Play rules may require in-app purchase for tips to the app, support and the M4 digital purchases (boost, Premium); if review objects, hide the payment entry points in store builds or move those purposes to IAP. Decide with the client before the first store submission.
