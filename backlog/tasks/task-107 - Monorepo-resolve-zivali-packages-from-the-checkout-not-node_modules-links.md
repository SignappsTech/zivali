## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Agent worktrees share the main checkout's node_modules through a junction (pnpm hoisted layout). The workspace links node_modules/@zivali/* (and apps/*/node_modules/@zivali/*, packages/*/node_modules/@zivali/*) point at whichever checkout last ran an install. On 2026-10-16 an implicit install from one worktree re-pointed them all into that worktree, and main's verify then type-checked against that branch's stale packages (TS2561 on fields that exist on main). The lead re-pointed the junctions by hand. Even without that accident, a worktree agent that changes packages/types and apps/api together type-checks and tests apps/api against MAIN's packages/types, not its own branch's.

Make every consumer resolve @zivali/* from the checkout it runs in: TypeScript `paths` in the shared tsconfig base (relative to the repo root, pointing at packages/*/src), the same aliases in vitest (apps/api, apps/web, packages/*), jest moduleNameMapper (apps/mobile), Metro (apps/mobile resolver), and Next.js (transpilePackages already set; check its resolution follows the alias). Keep the published package exports as they are for the Docker build (tsup bundles from source).
