# C1 API and platform conventions

Applies to every endpoint, Prisma model, migration, job and seed in `apps/api`. Owners: the API scaffold task (TASK-3.7) and the platform tasks (TASK-6.2, TASK-6.12); later tasks extend, never fork.

## HTTP

- Base URL `API_URL` (local `http://localhost:4000`, staging `https://api.staging.<domain>`), all routes under `/v1`. Health: `GET /ping` → `{ "message": "pong" }` (liveness), `GET /v1/health/ready` → `{ ok, version, db, queue_lag_s }` (readiness, touches the DB).
- Auth header `Authorization: Bearer <Supabase access token>` (users and anonymous finders). Device header `x-device-id: <uuid>` on every request (C7). Language `Accept-Language: sl|en` (falls back to the profile locale).
- JSON only (`Content-Type: application/json`, max 1 MB); snake_case keys on the wire; dates ISO 8601 UTC strings; money as integer cents.
- Paths: kebab-case plural nouns (`/v1/reports`, `/v1/match-suggestions`), ids or short codes as params, actions as sub-resources (`POST /v1/matches/:id/confirm`). No verbs in paths otherwise.
- **No envelope.** A single resource is the object; a list is `{ "items": [...], "next_cursor": "…" | null }` (keyset pagination: `?cursor=&limit=`, `limit` ≤ 50 unless stated).
- **Errors**: always
  ```json
  { "error": { "code": "VALIDATION", "message": "…", "details": { … }, "issues": [{ "path": "location.lat", "message": "…" }] } }
  ```
  | Code | HTTP |
  |---|---|
  | `VALIDATION` | 400 |
  | `UNAUTHENTICATED` | 401 |
  | `FORBIDDEN`, `UNVERIFIED_EMAIL`, `AAL2_REQUIRED`, `UPGRADE_REQUIRED` (a Premium feature without the entitlement, `details.entitlement`; added by TASK-52, C13 §Prices and entitlements) | 403 |
  | `NOT_FOUND` | 404 |
  | `CONFLICT`, `DUPLICATE_OPEN_REPORT` | 409 |
  | `GONE` | 410 |
  | `MIN_AMOUNT`, `LIVE_MODE_FORBIDDEN`, `CAPTCHA_FAILED` | 422 |
  | `RATE_LIMITED` (+ `Retry-After` header, `details.retry_after_s`) | 429 |
  | `INTERNAL` | 500 (no details, logged with the request id) |
  | `SERVICE_UNAVAILABLE` | 503 (adapter explicitly switched off: `*_PROVIDER=off`) |

  Thrown as `new AppError(code, message?, details?)` from domain functions (`domains/<area>`); zod failures become `VALIDATION` with `issues`. No stack traces or SQL to clients. Clients map `code` to `errors.<code>` i18n keys.
- **Idempotency**: write endpoints that may be retried accept `Idempotency-Key: <uuid>` (required on `POST /v1/reports`, `POST /v1/payments/checkout`; optional on `POST /v1/pets`, mounted after auth and the `pets.write` rate limit: the same key and body replay the first answer for 24 h with `Idempotent-Replayed: true`, the same key with another body → `409 CONFLICT`; a `PET_LIMIT` 409 is a stored answer, so clients drop the key after it; `POST /v1/conversations/:id/messages` also honours it, C9). The `idempotency` middleware (`middleware/idempotency.middleware.ts`) stores `{ key, user_id, route, status, body (encrypted when it contains a secret), created_at }` in `app.idempotency_keys` for 24 h; the key is scoped to user + route + body hash; a repeat with the same key and body returns the stored response; the same key with a different body (or another user) → `409 CONFLICT`. 401/403 responses are never stored, and the middleware mounts after the guards (auth, role, aal2) so rejected requests never consume a key. The mobile outbox (C17) relies on it.
- **Rate limits**: `rateLimit(name, { limit, window, key: 'user'|'ip'|'device' })` middleware (`middleware/rateLimit.middleware.ts`) backed by `app.rate_limits` (Postgres, fixed window; IPs and device ids stored as HMAC with `RATE_SALT`, purged after 48 h). Defaults in `app_config` (`rate.*`).
- **CORS**: allowlist `WEB_ORIGINS`; requests without `Origin` (mobile) allowed. Security headers via helmet; Caddy adds HSTS.
- **Request id**: every response, errors included, carries `x-request-id` (generated by the `requestId` middleware unless the caller sent one; also in the pino logs). `@zivali/api` reads it into `ApiError.requestId` for the generic error message. Set by TASK-3.7.
- **Request log**: the log line of an error answer adds `error_code` and, for `VALIDATION`, `error_paths` (the issue paths, at most 10, no messages or values), set by the error middleware in `res.locals` (TASK-114.5).
- **OpenAPI**: zod schemas registered with `@asteasolutions/zod-to-openapi` (registry in `@zivali/validation`); the spec is written to `apps/api/openapi.json` and drives the `@zivali/api` RTK Query client (ADR-020 §Client). Swagger UI at `/docs` (local/staging; prod admin-only or off) is deferred to a low-priority task.

## Auth middleware and guards (`middleware/auth.middleware.ts`, `middleware/permission.middleware.ts`)

Middleware files follow the repo suffix convention: `auth.middleware.ts`, `permission.middleware.ts`, `rateLimit.middleware.ts`, `idempotency.middleware.ts`.

| Guard | Effect |
|---|---|
| `authMiddleware` | verifies the JWT (JWKS, `jose`), loads `req.user = { user_id, role, is_anonymous, aal, email_verified, locale }`; 401 otherwise |
| `optionalAuth` | same, never blocks (public endpoints that personalise, e.g. `is_mine`) |
| `requireVerified` | non-anonymous users need a confirmed email (`UNVERIFIED_EMAIL`); anonymous managers pass where the contract says so |
| `requireVerifiedOrAnonymous` | passes anonymous users and verified non-anonymous users; non-anonymous users with an unconfirmed email get `UNVERIFIED_EMAIL` (anonymous finder and manager flows) |
| `requireRole('moderator' \| 'admin')` | role from `app.profiles` (cached 60 s) |
| `requireAal2` | `aal === 'aal2'` (TOTP) for every staff route (`AAL2_REQUIRED`) |
| `rejectAnonymous` | routes that need a real account (payments, alerts) |

Ownership ("owner of pet", "manager of report", "participant of conversation") is checked in domain functions with helpers `assertCanManageReport(ctx, reportId)` etc., never in the client.

## Database (Prisma, schema `app`)

- Prisma 7 multi-file schema `apps/api/prisma/schemas/<domain>.prisma` (`base`, `users`, `reports`, `photos`, `matching`, `chat`, `notifications`, `abuse`, `payments`, `ads`, `geo`, `directory`, `platform`), `@@schema("app")` on every model, `datasource` with `schemas = ["app"]`. Naming per ADR-020: snake_case plural models without `@@map`, snake_case fields, `id String @id @default(uuid()) @db.Uuid`, `created_at DateTime @default(now()) @db.Timestamptz(6)`, `updated_at DateTime @updatedAt @db.Timestamptz(6)`, enums SCREAMING_SNAKE.
- PostGIS and pgvector columns are `Unsupported("extensions.geography(Point,4326)")` (schema-qualified, because `?schema=app` leaves `extensions` off the search path) / `Unsupported("extensions.vector(1024)")` and read or written only through TypedSQL (`prisma/sql/*.sql`) or `$queryRaw` with parameters.
- **Lockdown (ADR-021)**: the first migration creates schema `app`, enables `postgis`, `vector`, `pgcrypto` in schema `extensions`, revokes all on `app` and `pgboss` from `anon`, `authenticated`, `public`; every migration that creates a table also runs `alter table app.<t> enable row level security;` (no policies). A test fails otherwise (`test/security/schema-exposure.test.ts`).
- Migrations: `prisma migrate dev` locally; one migration per task (`<timestamp>_<task-id>_<slug>`), never edit a merged migration; hand-written SQL inside Prisma migrations for RLS, extensions, check constraints and the `realtime.messages` policy (ADR-023). Header comment in `migration.sql`: `-- task: TASK-x.y` and `-- rollback: …`.
- `app_config` (`key`, `value Json`, `is_public`, `description`): defaults inserted by each feature's migration or seeder (`on conflict do nothing`); read through `lib/config-store.ts` (cached 60 s); admin writes are audited. `GET /v1/config/public` returns the keys with `is_public = true` (feature and content flags such as `content.legal_timings`, `vet_partner.enabled`, `podpornik.enabled`, `share.facebook_groups`, `share.radio_form_url`, `flags.supporter_monthly`, `flags.transparency_page`), plus one computed key, `payments.enabled` (false when `PAYMENTS_PROVIDER=off`, C13 §Payments off), `Cache-Control: public, max-age=300`.
  - Share keys (public, TASK-24.2/24.3, CH-337): `share.facebook_groups` = `[{ name: string, url: https URL, regions?: C6 region slugs[] }]` (the report's region sorts first; the client supplies the list); `share.radio_form_url` = https URL of the local radio's announcement form (Radio Aktual), default unset (the row is hidden). Clients drop malformed or non-https entries.
- `audit_log` (`actor_id`, `action`, `target_type`, `target_id`, `diff`, `created_at`): written by `AuditDao.write(tx, …)` in every staff service call.
- Users: `profiles.id` equals the Supabase `auth.users.id` (no foreign key into `auth`); a profile is created on first authenticated request (`ensureProfile`). Deleting an account calls the Supabase Admin API and deletes or anonymises our rows in one service (M3).
- **Data inventory**: `apps/api/prisma/data-inventory.json` lists every model and R2 bucket (category, personal data, basis, retention, export, delete); a test fails when a model is missing.

## Jobs (pg-boss, ADR-022)

Adapters (`apps/api/src/adapters/*`: interface + mock + provider) are new code, not ported from any earlier branch.

`jobs.send(queue, data, opts)` from domain functions (`lib/jobs.ts`, via `ctx.jobs`), optionally inside the Prisma transaction. Handlers in `jobs/<queue>.job.ts` export `async function handle(data, ctx)` and call domain functions; `ctx = { prisma, logger, adapters, now, send }`; idempotent; throw to retry (5 attempts, backoff). Queue names in C1 order: `match.report`, `notify.send`, `alerts.fanout`, `photo.process`, `photo.publish`, `report.lifecycle`, `retention.purge`, `retention.blur_location` (daily 03:45 Europe/Ljubljana; ADR-006, `app_config` `retention.exact_point_blur_days` 30), `partners.stats`, `payment.effects`, `fiscal.resubmit` (hourly cron `25 * * * *`, Europe/Ljubljana: sends FAILED and long-PENDING invoices again, C13 §Fiscal invoices; TASK-92.3), `directory.reminder`, `db.keepalive`, `db.backup`; M3 adds `ai.extract` (C19), `photo.embed` and `embedding.backfill` (C20), registered with stubs by TASK-40.1. `payment.effects` is sent with per-job retry options from `app_config` `fiscal.retry` (`retryDelay` in minutes, `retryBackoff`, `retryDelayMax`), not only the queue default backoff. Tests and `pnpm jobs:drain` process queues to empty.

## Seed

`prisma/seed.ts` runs `prisma/seeders/<n>-<name>.seeder.ts` in order; each task owns its seeder file. Fixture users are created in local Supabase Auth through the Admin API (local service key) and get profiles: `owner@zivali.test`, `owner2@zivali.test`, `finder@zivali.test`, `shelter@zivali.test`, `mod@zivali.test`, `admin@zivali.test` (password `zivali-local-only`; local TOTP secret for mod and admin documented in the seed README). Seed photos are uploaded to MinIO.
