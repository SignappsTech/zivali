# C2 Design tokens package (`@zivali/tokens`)

## Input

`docs/design/tokens.json` (owned by the design lead; direction A "Lagoon", `$meta.version` 0.2.0, one theme with light and dark, no variants). Shape the generator relies on:

| Path | Shape |
|---|---|
| `primitives.color.<scale>.<step>` | hex |
| `primitives.fontFamily.{display,sans}` | CSS font stack (Bricolage Grotesque, Atkinson Hyperlegible Next) |
| `semantic.{light,dark}.<token>` | `"scale.step"`, `"#RRGGBB"` (map colours, brand-literal provider colours, coat swatches), or `{ "ref": "scale.step", "alpha": 0.16 }` |
| `elevation.{light,dark}.shadow-{sm,md,lg}`, `elevation.reactNative.{sm,md,lg}`, `elevation.usage` | CSS shadow / RN shadow props / guidance |
| `shape` | `radius` (base, `1rem`), per component `button`, `card`, `input`, `row`, `chip`, `sheet`, `photo` (scale names or px) |
| `scale.type`, `scale.space`, `scale.radius`, `scale.size`, `scale.motion`, `scale.breakpoint`, `scale.zIndex`, `scale.component` | numbers (px) or objects; `scale.component` = button, input, row, card, bottomnav, progress, sheet, marker sizes |
| `pairs.list` | `[foreground, background, minRatio][]` |

The generator validates this shape and fails with a clear message. A change to the shape is a `CHANGE docs/tech/contracts/C2-design-tokens.md` request to the tech lead; value changes need no tech involvement.

## Outputs (`packages/tokens/dist/`, generated by `pnpm --filter @zivali/tokens build`)

| Export | File | Consumer |
|---|---|---|
| `@zivali/tokens/tokens.css` | CSS variables (HSL triplets, `--primary: 190.3 65.5% 22.7%`) for `:root, .light` and `.dark`, plus `--radius`, `--radius-<component>`, `--font-display`, `--font-sans`, `--shadow-*` | web |
| `@zivali/tokens/web.css` | Tailwind 4 `@theme inline { --color-<token>: hsl(var(--<token>)); --radius-*; --font-*; --shadow-*; --text-* }` (shadcn "new-york" v4 vocabulary) | web `globals.css` |
| `@zivali/tokens/native.css` | same variables with NativeWind selectors `:root` and `.dark:root` | mobile `global.css` |
| `@zivali/tokens/tailwind-preset` | `tailwind-preset.cjs`: Tailwind 3.4 preset, colours `hsl(var(--x) / <alpha-value>)`, shadcn pairs nested (`primary.DEFAULT`, `primary.foreground`), app tokens flat (`status-lost-subtle`, `marker-area`), radius, fontFamily, fontSize, `minHeight`/`minWidth` touch sizes (44/48/56), boxShadow | mobile `tailwind.config.js` |
| `@zivali/tokens/values` | `values.ts`: `colors.light` / `colors.dark` (resolved hex per token), `space`, `size`, `component`, `radius` (px), `motion`, `zIndex`, `breakpoint`, `elevationNative`, `fonts` | navigation theme, status bar, PDF poster, haptics |
| `@zivali/tokens/map-style` | `map-style.ts`: `buildMapStyle(mode: 'light'|'dark', opts?: { detail?: boolean }): StyleSpecification` – OpenFreeMap "positron" style with the `map-*` tokens and the calm layer set (system §9; `detail: true` keeps minor streets for detail maps) | web and mobile `MapView` |

Token names equal CSS variable names (`status-lost-subtle-foreground` → `--status-lost-subtle-foreground`, Tailwind class `bg-status-lost-subtle`). The shadcn and RN Reusables base names (`background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, `chart-1..5`, `sidebar-*`) are always present.

## Rules

- The build fails (exit 1) if any `pairs.list` entry is below its ratio in light or dark, or references a missing token (reference behaviour: `docs/design/build-tokens.mjs`).
- Generated files are not committed; Turbo runs the build before the apps' `dev`, `build`, `test`, `typecheck`.
- Fonts: web loads Bricolage Grotesque and Atkinson Hyperlegible Next with `next/font/google` and maps them to `--font-display` / `--font-sans`; mobile uses `@expo-google-fonts/bricolage-grotesque` and `@expo-google-fonts/atkinson-hyperlegible-next` with the registered static names in the preset's `fontFamily`.
- `calc()` radii work in NativeWind 4; if a platform rejects them, the preset falls back to pre-computed px from `values.radius`.
- **Coat swatches** (tokens 0.6.0, system.md 3.2, CH-310, CH-621): `coat-black` … `coat-blue-grey` (10 literal hex values, the same in light and dark) and `coat-edge` (translucent: mist.950 at 0.24 light, mist.100 at 0.32 dark). The generator emits them like any token, with no code change: `bg-coat-<name>` and `border-coat-edge` on web (Tailwind 4) and mobile (NativeWind preset), `values.colors.*['coat-<name>']`. Use them only for the 16 px swatch before a colour word (P4 filter, P6/P8 colour pills); semantic or status tokens never stand in for a coat colour. The swatch is decorative (`aria-hidden`), the word carries the meaning.
- Do not add runtime theme variants; dark mode follows the OS with a manual override (system §12).

## Example (excerpt of generated `web.css`)

```css
@theme inline {
  --color-primary: hsl(var(--primary));
  --color-primary-foreground: hsl(var(--primary-foreground));
  --color-status-lost: hsl(var(--status-lost));
  --radius-lg: var(--radius);
  --font-display: var(--font-display);
}
```
