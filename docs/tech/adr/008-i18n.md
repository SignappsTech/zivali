# ADR-008: next-intl on web, use-intl on mobile, one ICU catalogue package

- Status: Accepted · Date: 2026-10-14 · Owner: Tech Lead
- Source: FR-036, NFR-I18N, P-5, FR-035 R-035.4

## Decision

- **`packages/i18n`** holds ICU MessageFormat catalogues per locale and namespace: `messages/sl/<ns>.json`, `messages/en/<ns>.json`. Each feature task owns its namespace files, so parallel tasks do not conflict. A build step merges them into `dist/{sl,en}.json`.
- **Key parity check** (`pnpm --filter @zivali/i18n check`): fails CI when a key is missing in either locale, when a placeholder differs, or when an SL plural message lacks `one`, `two`, `few` and `other`.
- **Web**: `next-intl` 4 with `localePrefix: 'as-needed'` (SL unprefixed, EN under `/en`), localised `pathnames` (contract C15), `hreflang` alternates, locale cookie, and the profile language synced on sign-in.
- **Mobile**: `use-intl` (the framework-agnostic core of next-intl) with the same catalogues and API (`useTranslations`, `useFormatter`); default SL unless the device language is English or the profile says otherwise. Hermes `Intl.PluralRules` support for `sl` is verified at startup; if missing, `@formatjs/intl-pluralrules` with `sl`/`en` locale data is loaded as a polyfill.
- **Formatting**: `Intl` only (dates, numbers, EUR, relative time), time zone `Europe/Ljubljana`. No date library.
- **Server text** (emails, push): Edge Functions import the merged catalogue JSON and format with the same ICU messages in the recipient's `profiles.locale`.
- **Breeds** and other enums are codes in the DB and labels in catalogues; unknown codes fall back to "Mešanec / neznano" ("Mixed / unknown").

## Alternatives

- i18next on both: different API from next-intl on web; ICU needs a plugin.
- Lingui: compile step and macros complicate Metro and Deno.

## Consequences

- Copy changes are JSON edits in one package, reviewed by the content strategist.
- Slovenian dual forms are enforced by tooling, not by memory.
