# Backend slice (supabase/, scripts/, packages/types database types)

Read this, your task packet and the contract(s) it references. Conventions for every migration, policy, RPC, job and seed are in **C1** (`docs/tech/contracts/C1-platform-conventions.md`). Never open the masters (`docs/0*.md`). If the packet is not enough, report `needs-input`.

## Stack

- Supabase (CLI 2.x, local Docker stack): Postgres 17 with `postgis`, `vector`, `pgmq`, `pg_cron`, `pg_net`, `pgcrypto`; Auth (email, Google, Apple, anonymous, TOTP MFA, custom access token hook, Turnstile captcha in cloud); Storage; Realtime (Postgres Changes); Edge Functions (Deno).
- The API is Supabase itself (ADR-003): RLS on every table; `security definer` RPCs for public reads and multi-step writes; Edge Functions only for secrets and external calls (`worker`, `payments-checkout`, `stripe-webhook`, `submit-lead`, `health`).
- Async work: one pgmq queue `jobs`, `enqueue_job()`, `worker` function with one handler file per job type (C1 §Job queue).
- Shared pure TypeScript (zod schemas, chip normalisation, matching score) in `packages/validation`, imported by Edge Functions through `supabase/functions/deno.json` (`"@zivali/validation/": "../../packages/validation/src/"`, `"zod": "npm:zod@4"`).
- Tests: pgTAP (`supabase test db`), Vitest for function logic and integration (ADR-015).

## Ownership and shared files

- Migrations: always a new file; change a function with `create or replace` in your own migration. Two tasks never edit the same migration.
- Seed: your own `seed/NN-<task>-*.sql`; the shared fixture users and base reports come from TASK-6.
- Worker: replace only your handler file (`handlers/<type>.ts`); the registry is fixed by TASK-6 with stubs for all M2 job types.
- `create_report` belongs to the report-write task (@@report-write-be@@); the anonymous guard is a separate function `submission_guard(p jsonb)` (stub from @@report-write-be@@, real body from @@anon-be@@).
- `enqueue_notification()` belongs to the notifications task; until it is merged, call it anyway (the TASK-6 stub enqueues `notify` jobs that the stub handler logs).
- `app_config` keys: insert your defaults in your migration (`on conflict do nothing`).

## Standards

- Every table: RLS enabled in the same migration, policies from C1 templates, pgTAP RLS matrix rows for anon, anonymous-signed-in, owner, other user, manager, moderator (aal2), admin (aal2).
- Every RPC: `security definer`, `set search_path = ''`, fully qualified names, explicit `auth.uid()` and role checks, validated input, stable error codes (C1), audited if staff-only, idempotent where retried (`p_client_request_id`).
- Public reads never return `exact_point`, `chip_number`, `manage_token_hash`, emails, phone numbers or `created_by` (C4 §Public read model).
- Jobs: idempotent (upserts, unique keys, dedupe keys); chunk fan-outs ≤ 500; never call external services inside SQL transactions.
- Edge Functions: validate input with zod; adapters chosen by env; `mock` is the default whenever a credential is missing; JSON logs `{ level, msg, fn, request_id, job_type?, duration_ms }` with no PII or secrets; CORS only for `APP_URL` origins; return `{ error: { code, message, details } }`.
- Privacy: new table or bucket → entry in `supabase/data-inventory.json` (pgTAP fails otherwise); retention handled in `purge_retention`; IPs only as keyed hashes.
- Security: SQL only through parameters / `format('%L')`; no service key in clients; webhook signatures verified; no SSRF (no fetching user-supplied URLs in M2).

## Error handling

RPC: `raise exception using errcode = 'P0001', message = json_build_object('code', …, 'message', …, 'details', …)::text`. Edge Functions: HTTP status (400 validation, 401/403 auth, 404, 409 conflict, 410 gone, 429 rate limited, 500) + error JSON. Unexpected errors: log with `request_id`, return `INTERNAL` without details. Jobs: throw to retry (max 5, then `jobs_dead` with the error).

| Command | What |
|---|---|
| `pnpm bootstrap` | install, `supabase start`, `supabase db reset` (migrations + seed), `scripts/seed-photos.mjs` |
| `pnpm db:start` / `db:stop` / `db:reset` | local stack lifecycle |
| `pnpm db:test` | `supabase test db` (pgTAP) |
| `pnpm db:lint` | `supabase db lint` (also flags missing RLS, security definer issues) |
| `pnpm db:drain` | run the worker until the queue is empty |
| `pnpm gen:types` | regenerate `packages/types/src/database.ts` |
| `pnpm functions:serve` | serve Edge Functions locally (`supabase functions serve --env-file supabase/functions/.env.local`) |
| `pnpm functions:check` | `deno check` all functions |
| `pnpm --filter functions test` | Vitest for function logic and integration |
| `pnpm admin:create <email>` | promote an existing local account to admin |
| `node scripts/deploy.mjs staging --dry-run` | credential-gated deploy (ADR-016) |
| `pnpm verify` | everything CI runs (required before reporting done) |

## Definition of Done and gate checklist

- [ ] Acceptance criteria met and demonstrated (pgTAP/Vitest output, example requests)
- [ ] Contract followed exactly (names, shapes, error codes); deviations reported as `CHANGE docs/tech/contracts/C<n>…`
- [ ] RLS enabled and RLS matrix tests for every new table; pgTAP for every new RPC, trigger and policy
- [ ] `supabase db reset` from zero works; migration has the task and rollback header
- [ ] `pnpm gen:types` run and committed when the schema changed
- [ ] `pnpm verify` passes (lint, typecheck, `deno check`, unit, pgTAP, build, e2e smoke)
- [ ] Data inventory updated; retention handled; no PII in logs; IPs hashed
- [ ] Mocks keep everything working offline; credential-gated parts report `needs-input` instead of failing
- [ ] No secrets in code or output; no new dependency outside ADR-017
- [ ] No unrelated changes; README / function README updated where behaviour or commands changed
