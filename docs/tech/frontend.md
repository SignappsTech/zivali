## Ownership and shared files

- **Root layouts and providers** are owned in this order, each later task depends on the earlier: web `app/[locale]/layout.tsx`, `providers.tsx`, `proxy.ts`: scaffold → i18n web → tokens/theme binding → web shell → auth web / analytics web / consent web. Mobile `app/_layout.tsx`: scaffold → i18n mobile → tokens/theme binding → mobile shell → analytics mobile / auth mobile / consent mobile. Touch them only if your task is in that chain.
- **i18n**: add keys only in your feature's namespace files (`packages/i18n/messages/{sl,en}/<ns>.json`); both locales in the same commit. Copy comes from the content slice; if missing, use a clear SL+EN draft and list the keys in your report (`CHANGE docs/content/...` request).
- **`@zivali/api`** (ADR-020 §Client): `createApiClient({ baseUrl, getAccessToken, deviceId, locale })` adds `Authorization`, `x-device-id`, `Accept-Language` and `Idempotency-Key` where the contract requires it and parses `{ error }` bodies into `ApiError` (`x-request-id` response header → `ApiError.requestId`, C1). `src/rtk.ts` turns it into the RTK Query `baseQuery` and exports `createApiStore`; endpoints and hooks are **generated** from `apps/api/openapi.json` by `@rtk-query/codegen-openapi` (`openapi-config.ts`, `pnpm --filter @zivali/api gen:api` → `src/generated/endpoints.ts`, never edited by hand); keyset helpers in `src/pagination.ts`. Hand-written code is limited to what codegen cannot express (`geocode.ts`, photo upload with progress, Realtime, hooks such as `useSession`) and is exported by subpath (`@zivali/api/<name>`); no barrel edits. Until a backend endpoint is merged and in the spec, UI tasks use `createMockApi()` and fixtures (`src/__fixtures__/<domain>.ts`); never wait for the backend. Never call Supabase tables from the apps: `supabase-js` is only for Auth and Realtime channels.
- **`@zivali/api` generation** (TASK-114.35, CH-658, CH-659): `gen:api` generates only the operationIds listed in `openapi-config.ts` `filterEndpoints`. `injectEndpoints` keeps the first definition of a name, so a stub and its generated twin shadow each other by import order (generating the full set would hide hand-written infinite queries such as `useSearchReportsInfiniteQuery`). To drop a stub: add its operationId, run `gen:api`, build the domain module on the generated `enhancedApi` (see `photos.ts`). Infinite lists stay hand-written. `createReport` stays hand-written until the API declares `Idempotency-Key` as an OpenAPI header parameter (C1: one stable key per form submit or outbox item; the generated one would send none).
- **Report detail slots**: fill your slot in `components/report/slots/<name>.tsx`; do not edit the detail page layout unless your task owns it.
- Generated files (`packages/tokens/dist`, `packages/i18n/dist`) are never edited by hand.
- **Workspace packages** (TASK-107): `@zivali/*` source resolves from the checkout's own `packages/*/src` through tsconfig `paths` (tsc, vitest, Next.js, Expo's Metro) and mobile jest `moduleNameMapper`, never through the `node_modules/@zivali` links, which in a worktree point at the main checkout.
- A new `@zivali` export (or subpath) gets an entry in `tsconfig.base.json`, `apps/web/tsconfig.json`, `apps/mobile/tsconfig.json` (each app's `paths` replaces the base's) and the jest `moduleNameMapper`; tokens `values`/`map-style` and `i18n/dist` resolve to `dist/` the same way; only the CSS, tailwind-preset and `app.config.ts` still go through node_modules. After a paths-only change, touch the vitest configs or run `vitest --clearCache` (vitest 5's cache keys only on the config file) Built outputs (tokens `values`/`map-style`, `i18n/dist`) try the worktree's own `dist/` first, then `node_modules/@zivali/*` (main's copy); run `node build.mjs` in packages/tokens and packages/i18n (or any turbo task) to use the worktree's own dist..
- **Root config** (`package.json`, `turbo.json`, `tsconfig.base.json`, `eslint.config.mjs`, `.prettierrc.json`, `.editorconfig`, `.husky/`, `pnpm-workspace.yaml`) is owned by the workspace tasks (TASK-3.1, TASK-3.8; TASK-4.1 and TASK-4.2 finish the `quality` and `verify` scripts); do not edit it otherwise. App package names are unscoped: `web`, `mobile` (and `api`), so `pnpm --filter web …` works; shared packages are `@zivali/*`. Each app adds its framework ESLint preset in its own `apps/<app>/eslint.config.mjs` that spreads the root base, and its own `tsconfig.json` that extends `../../tsconfig.base.json`. Add app dependencies to the app's `package.json`. The one exception to the rule above: a dependency with an install script fails `pnpm install` until it is listed under `allowBuilds` in `pnpm-workspace.yaml`; add one line (`<name>: true`) only if the script is really needed, and name it in your report.

## Standards

- TypeScript strict, no `any` without a comment; ESLint + Prettier clean (klikni style: tabs, print width 120, single quotes, imports grouped builtin / external / internal with a blank line between, `import-x/order`; husky + lint-staged run `eslint --fix` and `prettier --write` on commit). The root ESLint base ends with `eslint-config-prettier`; keep it last when an app config spreads the base and adds its preset after it (`[...base, ...preset, prettier]`).
- Components use semantic tokens only (no hex, no primitives); cards flat (no border, no shadow); status = icon + word + colour; one `h1` per page; targets ≥ 44 px; visible labels above fields; errors as text + icon tied with `aria-describedby`; reduced motion honoured (design system §12).
- Same component names and props on web and mobile (`Button`, `Input`, `FormField`, `StatusLabel`, `MapView`, `LocationPicker`, `ReportSlot`, `AdSlot`, …).
- Web: server components by default; `"use client"` only where needed; MapLibre, PDF and heavy code via dynamic import; images with explicit width/height; no layout shift (reserved sizes for photos and ad slots).
- Mobile: safe areas, OS font scaling up to 200 % (`maxFontSizeMultiplier` 2), permission primer before every OS prompt (camera, location, notifications) with a working fallback on denial.
- Location privacy (ADR-006, C6 §Storage): call `coarsenPoint()` (`@zivali/validation/geo`) once when the user picks or confirms a point (GPS, pin, search, EXIF) and hand only the coarsened point to forms, drafts, the offline outbox and requests; the raw value stays in component state. Show the owner's stored point labelled "približno" (`location.approximate_label`). Lookup URLs (`near`, `bbox`, sync `areas`, shelters) use coordinates rounded to 2 decimals, `bbox` rounded outwards (C4 §REST). `coarsenPoint()` is built by the packages/validation task (20–30 m random coarsening once at write, C6); LocationPicker tasks depend on it.
- Privacy: never render or log exact coordinates, chip numbers, emails or phone numbers of other users; `track()` only with registered params (C12); no PII in `console` output.
- Analytics instrumentation (C12b): a wizard or multi-step flow keeps one `flowTracker(flow)` in a ref, calls `step()` when a step shows and `error(step, code, field?)` once per refused attempt (the form's field key and a C12b §4 code, never the value or the message). Component tests assert what the `mock` adapter received (`getMockEvents()` after `setConsent({ analytics: true })`), including that nothing is recorded without consent. The registry (`packages/analytics/src/registry.ts`) is edited only by its owner task.
- Device storage (mobile): only the C17 tables (own drafts and outbox, public report cache) and secure-store tokens; never persist chat, matches, notifications or other private queries (no redux-persist or other query persistence); screens read report lists only through `lib/data/reports.ts`; sign-out calls `wipeLocalData()`.
- Photo frames (TASK-114.43): every report or pet photo in a card, row, thumb or marker crops cover anchored at 50% 10%; full views show the whole photo (contain) on muted. Web: `lib/photo.ts`; mobile: expo-image `contentFit="cover"` + `contentPosition={{ left: '50%', top: '10%' }}`, or `contain` (TASK-114.44). Never a centre crop.
- Accessibility first: every map has a list alternative; every icon-only button has an accessible name; dialogs and sheets trap and restore focus.
- Redux and the bundle (CH-314, CH-363): a client component reachable from the root layout or a public page must not statically import `@zivali/api/*` hooks; load it with `next/dynamic`, or every public page ships Redux/RTK (25 KB gz). `apps/web/eslint.config.mjs` enforces it with `no-restricted-imports` banning `use*` imports from `@zivali/api/*` in public routes, the root layout and home, `app/providers.tsx`, components/{shell,consent,analytics,content,legal}, the public auth forms and shelter-search (`eslint.config.test.ts`); a component that a public page imports statically joins that list. A new client namespace on a public page goes into `CLIENT_NAMESPACES` or the page's `PageMessages`.
- i18n on the client (TASK-90.7, CH-397): the root layout has no `NextIntlClientProvider`, so a public page ships no next-intl or use-intl code. The shell's client islands (`app/providers.tsx`, the consent banner, `ScreenViews`, `components/shell/parts.tsx`) get their strings as props from the server components that render them (`useLanguageLabels`, `consentCopy`) and the route from `@/i18n/client-navigation` (`useRoute`). A client component that translates needs a provider above it: `PageMessages` (a server component; on public pages above every such component, `AuthMain` included), the (app), (admin) or dev layout, or one inside a lazy island (SessionSync, the inbox dot, the 500 page). `@/i18n/navigation` keeps next-intl's typed API (Link, getPathname, redirect) without its runtime; the hooks (usePathname, useRouter) live in `@/i18n/client-navigation`. Both run on the pure mappings in `@/i18n/route.ts`, which a test checks against next-intl's `createNavigation` for every route. Runtime imports of `next-intl/navigation` are lint-banned (its client Link wrapper put use-intl on every page).
- Auth bundle (TASK-9.9, CH-652): `apps/web/eslint.config.mjs` also bans a static `@/lib/auth` import in the public block (supabase-js + zod + RTK, about 190 KB gz) and lists `components/auth/provider-buttons.tsx`; public auth forms import `@/lib/auth-light` and call `loadAuth()`. They use `useCaptcha({ lazy: true })`; sonner loads only for the sign-in notice toast (`components/auth/notice-toast.tsx`; `AuthMain` has no Toaster).
- No ad component in protected flows (C15): report-lost, report-found, manage, inbox and conversations, sign-in/up/reset, payments return.
- Toasts (decision CH-550; planned, TASK-114.46): one sonner `<Toaster>` per layout that needs toasts (the (app) and (admin) layouts, the `/m` page island), mounted outside `<main>` so toast text never sits in the main landmark; components only call `toast()` and never mount their own. Not in the root layout: public pages ship no sonner (the auth notice toast stays lazy, TASK-9.9). Today several components mount a Toaster inside `<main>` (TASK-114.28 e2e flake).
- Sign-out on web (CH-401, CH-218; planned, TASK-9.10): deletes the idb-keyval `photos:*` and `draft:*` keys and the manage tokens (`manage:*`, sessionStorage `manage_token`); drafts carry their owner's user id (C5 §Client).

## Error handling

- `@zivali/api` throws `ApiError { code, message, details }` (codes in C1). Map `code` to `t('errors.<code>')`; show inline for forms, toast for background actions, an error state component for pages.
- Network errors: RTK Query (`@zivali/api/rtk` `createApiStore`; hooks generated by `pnpm --filter @zivali/api gen:api`) retries 2× for network/5xx errors on queries only, never for 4xx or mutations; forms keep user input; drafts persist (C4 §Drafts).
- Unknown errors: generic localised message + `request id` if available; never raw messages or stack traces.
- Status of `/r/[code]` (TASK-18.2, CH-408): the 410 (and 404) is set in `proxy.ts`, because App Router pages cannot set a status. Document requests ask `GET /v1/reports/:code` as the viewer before routing, so each detail view costs two API reads; RSC navigations skip it. A held report answers 404 to non-managers on purpose (C4 reads held as unknown; C15).
- Next: `error.tsx` per route group, `not-found.tsx`, and the 410 "no longer available" page for `GONE`.

## Git

Branch `agent/<task-id>-<slug>` from `main`; commits `<task-id>: <what>`; never merge; report with screenshots (mobile 390 px and desktop 1440 px for web UI; Android screenshots for mobile UI).

### Worktrees (agents)

Windows + pnpm 11 hoisted: a `pnpm install` inside an agent worktree can delete tracked files when a prune hits EPERM on `node_modules` junctions (TASK-87.1 and 35.2, 2026-10-15). Agents avoid installs in worktrees; when one is needed, remove the `node_modules` junctions with `rmdir` first, and check the tree afterwards (CH-235).

### Native modules (mobile)

`expo-location` (TASK-87.1) is a native module: a new dev build / EAS rebuild is needed; iOS background mode `location`, Android background location. A revoked Always permission is noticed on resume or after a cache sync, not instantly (CH-234). `@maplibre/maplibre-react-native` also needs a dev build (ADR-017).

## Definition of Done and gate checklist

- [ ] Acceptance criteria met and demonstrated (screenshots / test output)
- [ ] Matches the design page slice and `docs/design/system.md` (tokens only, states: default, focus, disabled, error, loading, empty)
- [ ] Copy from the content slice, SL and EN complete; `@zivali/i18n check` passes
- [ ] Tests added or updated: unit/component for logic and states; Playwright for new web routes; jest-expo for new mobile screens
- [ ] `pnpm verify` passes (format, lint, secretlint, typecheck, unit, i18n, tokens, API tests, build; audit and e2e smoke run in CI, run them locally when dependencies or web pages change)
- [ ] Gates for touched web pages (`lighthouserc.json`, docs/05 §Quality gates): Lighthouse perf ≥ 90 (map ≥ 0.65), a11y ≥ 95, SEO ≥ 95 (public pages), lab LCP ≤ 3.3 s (2.5 s is asserted on staging), CLS < 0.1, script ≤ 256 000 B (`/prijava/*` ≤ 300 000 B, map ≤ 730 000 B); axe 0 violations; 0 broken links
- [ ] No ad slot in protected flows; no analytics request or `_ga` cookie before consent
- [ ] Keyboard and screen reader checked on the new UI; touch targets ≥ 44 px; works at 320 px width and 200 % text
- [ ] No PII in logs or analytics; no secrets in code; no new dependency outside ADR-017
- [ ] Mobile: nothing private written to device storage beyond C17; offline and error states explicit; no background location without opt-in
- [ ] No unrelated changes; README or package README updated if behaviour or commands changed
