P16 Sign in and account creation

Quick, calm sign-in and sign-up with e-mail, Google or Apple; e-mail confirmation and password reset; the account gate that other flows open, which never loses a draft; account linking; and every error state. App frames are 390 px, web frames 1200 px. Copy is final from the P16 content slice (v0.1, native review pending). Finders reporting without an account never see these screens.

One primary per viewLabels above line fieldsGoogle and Apple: equal size, neutral tone, brand glyphsWeb: flow variant, 440 px column, no ads, no sidebarGate: "Vse, kar ste vnesli, ostane."

A. App: sign in and create account

Full-screen with a close button; close returns to where the user was. The primary sits in the page flow under the fields and docks above the keyboard while typing. Focus lands on the h1 when a screen opens.

B. App: confirm e-mail and reset password

Check e-mail and verified are single-message screens: a spot icon, the h1, one sentence, and the actions at the bottom. Forgot password and new password are single-question screens with a 64 px field.

C. App: the account gate, linking and session expiry

The gate is a bottom sheet over the step that needs an account. It stays short, so the draft remains visible above it: what the user entered is still there, which is the promise in the sheet. After success the user returns to exactly the same step.

D. App: errors

Errors say what happened and what to do, in text with an icon, never colour alone. Field errors use the destructive line; everything about the whole form is a single message under it.

E. Web at 1200 px

Flow variant from P1: reduced header (logo, "Zapri"), a centred 440 px column, the minimal footer row. No ads, no sidebar, no side panel. Enter submits. Below 1024 px the same column takes the full width with 20 px gutters.
