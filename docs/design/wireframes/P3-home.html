Homepage rework: two layout options

Component mock from the real tokens and components. Testers called the current page "a bit meh", so A and B differ in structure, not in colour. Use the toggles on each frame (state and viewport). Annotation boxes with dashed borders show the data each block needs.

  • P3 Home (TASK-115.1)
  • P1 Footer (TASK-116.1)
  • Alerts mock (TASK-114.15)
  • Legal table mock (TASK-114.19)

Questions for the owner

  1. Layout A (compact hero, report cards first) or B (chooser hero with photo, list + map)? A mix is possible: tell me which parts.
  2. Show the latest reports to everyone on the home page, with only status, species, approximate area and time (no names, no exact place)?
  3. Keep the live numbers block (needs a new public stats endpoint, hidden while numbers are small) or drop it for now?
  4. Should "Opažena žival" (sighted) be a visible home action (B has it in the hero, A a quiet link) or stay only in the header menu?

Option A: reports first, compact hero

Text-led hero with the two report CTAs, then the live feed straight under it. Idea: a visitor sees that real animals are being helped before reading how it works. Order: hero, latest reports (cards), numbers (optional), how it works (3 columns), safe by design, shelters, closing CTA band.
